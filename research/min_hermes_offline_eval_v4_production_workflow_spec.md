## 한줄 결론

기존 티커 아트로포스 퍼널은 조사, 전략, 엑스, 랜딩, 유지에는 강하지만, 지금 민의 실제 작업 변화인 피그마 엠시피, 디자인 엠디, 지피티 이미지 투, 럽아트 시댄스, 코덱스 씨엘아이, 알피 씨엘아이 게이트를 묶는 제작 라우팅은 직접 평가하지 못한다.

따라서 다음 티커 아트로포스 연구는 콘텐츠 카피 품질이 아니라 `헤르메스가 작업을 올바른 실행 표면으로 보내고 검증까지 닫는가`를 평가해야 한다.

- 하지만 결과는 일반적인 `신뢰 근거 제안`, `후기 블록 위치`, `예비 고객을 위한 신뢰 근거 제안`으로 압축되었다.
- 즉 현재 풀 퍼널 러너는 민의 에이전트 운영 개선 연구를 콘텐츠 전환 문제로 오분류한다.

이건 실패가 아니라 다음 연구 방향을 보여주는 좋은 증거다. 새 환경은 콘텐츠 퍼널이 아니라 제작 운영 라우터를 평가해야 한다.

## 평가 과제 다섯 개

### 일. 웹사이트 제작 요청 라우팅

요청:

`새 랜딩페이지를 만들고 싶다. 피그마 시안, 디자인 엠디, 지피티 이미지 투 이미지, 코덱스 씨엘아이 구현, 브라우저 검증까지 연결해줘.`

반드시 보여야 할 것:

- 알피 씨엘아이
- 디자인 엠디
- 피그마 유즈
- 코덱스 씨엘아이
- 브라우저 검증
- 빌드

실패 신호:

- 디자인 엠디만 만들고 끝냄
- 피그마 선행 누락
- 브라우저 검증 없이 완료

### 이. 지피티 이미지 투에서 시댄스 영상까지 이어지는 요청 라우팅

요청:

`지피티 이미지 투로 제품 이미지를 만들고, 럽아트에서 시댄스 이점영 영상까지 실험해줘.`

반드시 보여야 할 것:

- 오픈에이아이 코덱스 지피티 이미지 투 워크플로우
- 파일 존재 확인
- 럽아트
- 시댄스
- 점수표
- 다음 변수

실패 신호:

- 이미지 생성만 하고 영상 학습 질문 없음
- 모델과 파일 경로 없음
- 유지할 것, 버릴 것, 다음 변수가 없음

### 삼. 피그마 구현 요청 라우팅

요청:

`피그마 파일을 기준으로 지금 웹 앱 화면을 맞춰줘. 디자인 엠디도 같이 써줘.`

반드시 보여야 할 것:

- 피그마 유즈
- 스크린샷
- 디자인 문맥
- 디자인 엠디
- 드리프트
- 코드 반영

실패 신호:

- 피그마 값을 임의 추측
- 디자인 계약과 충돌 여부 미기록
- 화면 비교 없음

### 사. 헤르메스 안 코덱스 씨엘아이 실행 요청 라우팅

요청:

`이 저장소 버그를 코덱스로 고쳐줘. 헤르메스가 알아서 검증해줘.`

반드시 보여야 할 것:

- 알피 씨엘아이
- 수락 기준
- 코덱스 씨엘아이
- 변경 파일
- 테스트
- 헤르메스 최종 검토

실패 신호:

- 코덱스에게만 맡기고 끝냄
- 테스트 없음
- 변경 파일 확인 없음

### 오. 연구 결과 옵시디언 기록 요청 라우팅

요청:

`최근 작업 변화를 바탕으로 헤르메스를 민에게 더 맞게 개선하는 연구를 진행해줘.`

반드시 보여야 할 것:

- 큐엠디
- 알피 씨엘아이
- 티커 아트로포스
- 옵시디언 노트
- 평가 세트
- 검증 근거

실패 신호:

- 계획만 말함
- 기존 노트를 찾지 않음
- 연구 산출물이 파일로 남지 않음

## 운영 해석

이번 연구의 핵심은 모델 이름이 아니다.

지피티 오점오, 지피티 이미지 투, 시댄스, 피그마 엠시피, 디자인 엠디, 코덱스 씨엘아이의 공통점은 모두 민의 제작 공정을 빠르게 만들지만, 잘못 섞이면 검증 없는 자동화가 된다는 점이다.

그래서 헤르메스는 앞으로 다음 역할을 우선해야 한다.

- 작업을 올바른 경로로 보낸다.
- 선행 도구를 빠뜨리지 않는다.
- 코덱스나 스킬의 완료 메시지를 그대로 믿지 않는다.
- 파일, 테스트, 브라우저, 점수표로 직접 검증한다.
- 좋은 규칙은 옵시디언과 스킬, 티커 평가 세트로 승격한다.

## 바로 적용할 운영 규칙 초안

- 코드, 저장소, 랜딩페이지 작업은 알피 씨엘아이 게이트를 먼저 통과한다.
- 피그마 작업은 피그마 유즈 선행 후 디자인 문맥과 스크린샷을 남긴다.
- 디자인 엠디는 창의 디자인 결과물이 아니라 토큰과 결정 계약서다.
- 이미지 작업은 오픈에이아이 코덱스 지피티 이미지 투 워크플로우를 우선한다.
- 영상 작업은 럽아트와 시댄스 결과만 보지 말고 학습 질문, 기준군, 변형, 점수표, 다음 변수를 남긴다.
- 코덱스 씨엘아이는 실행 엔진이고, 헤르메스가 수락 기준과 최종 검증을 책임진다.
- 완료 보고에는 사용 경로, 산출물 위치, 검증 근거가 반드시 있어야 한다.
