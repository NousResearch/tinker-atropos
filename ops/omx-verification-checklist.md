# 옴엑스 검증 체크리스트

작성일: 2026-04-15

## 목적
옴엑스가 작업을 끝냈다고 말해도, 루나가 같은 기준으로 다시 확인할 수 있게 검증 순서를 고정한다.

## 착수 전
1. 민이 옴엑스를 명시적으로 요청했는지 확인한다.
2. 작업 목표를 한 문장으로 적는다.
3. 검증 완료 기준을 먼저 적는다.
4. 현재 더티 상태를 저장한다.
   - `git status --short`
5. 작업 범위를 적는다.
   - 바꿀 파일
   - 건드리면 안 되는 파일
6. 사용자에게 모드 선택을 다시 묻지 않는다.
   - 필요한 명확화는 `deep-interview`
   - 필요한 계획 고정은 `ralplan`
   - 실행은 `ralph` 또는 `team`
   로 omx 내부에서 처리한다.
7. tmux 세션 이름과 실행 경로를 먼저 정한다.
   - omx는 반드시 tmux 안에서 Codex를 실행한다.

## 실행 중
1. 옴엑스 모드를 기록한다.
   - `옴엑스 딥 인터뷰`
   - `옴엑스 랄플랜`
   - `옴엑스 실행`
   - `옴엑스 랄프`
   - `옴엑스 팀`
2. 사용 프롬프트 핵심 문장을 남긴다.
3. 로그 경로를 남긴다.
4. 상호작용 승인이나 예외 판단이 있었다면 짧게 적는다.

## 실행 직후 필수 검증
1. 워킹트리 재확인
   - `git status --short`
2. 이번 변경 파일 확인
3. 관련 차이 확인
   - `git diff -- <변경파일>`
4. 관련 시험 실행
5. 산출물 또는 빌드 결과 확인
6. 실패가 있으면 성공 보고 금지

## 완료 보고 필수 항목
- 작업 목표
- 사용 모드
- 변경 파일
- 실행한 검증
- 결과
- 로그 경로
- 기존 더티 상태와 새 변경의 분리 여부

## 실패 판정 기준
아래 중 하나라도 해당하면 완료로 보고하지 않는다.
- 더티 상태 분리가 안 됨
- 검증 명령이 없음
- 시험 실패
- 로그나 산출물 경로가 없음
- 옴엑스가 수정했지만 실제 반영 파일을 확인하지 못함

## 권장 보고 형식
```text
작업 목표: ...
사용 모드: ...
변경 파일: ...
검증: ...
결과: 성공 또는 실패
로그: ...
더티 상태 분리: 가능 또는 불가
```

## 최소 명령 묶음
```bash
git status --short
git diff -- <변경파일>
<관련 시험 명령>
```

## 운영 해석
- 옴엑스의 완료 선언은 초안일 뿐이다.
- 최종 완료 판단은 루나의 재검증으로만 닫는다.
